# Завдання: Спеціалізовані замовлення Етно-майстерні 🧵🏺

## Мета
Опанувати принципи наслідування, роботу з абстрактними класами та інтерфейсами.

## Структура проекту

### 1. Інтерфейс `IExportable`
- Метод `string GetExportString()` — повертає короткий рядок для наклейки на товар.

### 2. Абстрактний клас `Order` (Base Class)
- **Поля:** `Material`, `Region`, `Days`, `BasePrice`.
- **Конструктор:** ініціалізує базові поля.
- **Абстрактний метод:** `decimal GetFinalPrice()`.
- **Virtual метод:** `ToString()` для базової інформації.

### 3. Клас `ClothingOrder` (Derived Class)
- **Поле:** `Size` (наприклад, S, M, L).
- **Override:** `GetFinalPrice()` (додає 10% до ціни, якщо це вишивка на льоні).
- **Override:** `ToString()` (додає розмір до виводу).

### 4. Клас `PotteryOrder` (Derived Class)
- **Поле:** `Volume` (об'єм у літрах).
- **Override:** `GetFinalPrice()` (якщо об'єм > 2л, додає вартість за складність випалу).
- **Override:** `ToString()` (додає об'єм до виводу).

## Завдання для виконання
1. Реалізуйте ієрархію класів.
2. У файлі `Program.cs` змініть логіку: після запиту типу виробу (Одяг/Посуд), запитуйте відповідну характеристику (Розмір 
або Об'єм).
3. Використовуйте `List<Order>` для збереження всіх об'єктів.
4. В кінці програми, окрім аналітики LINQ, виведіть "Етикетки" для всіх товарів, використовуючи інтерфейс `IExportable`.

## Критерії успіху
- Програма не "падає" при створенні різних типів замовлень.
- Використано ключові слова `abstract`, `override`, `base`.
- Список `List<Order>` містить об'єкти різних типів (Поліморфізм).
